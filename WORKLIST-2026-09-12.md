## NEW BUILD — "Gigi's Rewards" customer accounts (replaces the VIP club signup)

### Owner's intent
People create an account (username + password). Inside the account they see their **free-pie code**, their **order history**, and we get to **track what they order** and **upsell at checkout** when something they usually order isn't in the cart.

### What exists today that we keep
- `vip_members` (identity: phone / email / addr_key partial-unique indexes = one pie per household), `vip_promo_codes` (`PIE-XXXXXX`, 90-day expiry, reserve→redeem at pay), email-verification flow (`vip_email_verifications`, `/vip-verify/`), consent capture + `consent_events`, `web_orders` ledger, checkout `body.vip` join-at-checkout, the cart-drawer upsell rail ("Add these to your order", 3 generic items), Turnstile + `rateLimit` + `adminAuth` helpers, Resend/Twilio wrappers, admin dashboard.

### Recommended design
1. **Username = email** (shown as "email or phone" on the login form; phone maps to the account's verified phone). Free-form usernames add support burden and collisions; the owner's "username + password" is satisfied with email as the username. Store `username_lower` (citext or `LOWER()` index) — fixes SB-7/LB-14 at the same time.
2. **Tables (both DBs, same migration):**
   ```sql
   CREATE TABLE accounts (
     id BIGSERIAL PRIMARY KEY,
     business TEXT NOT NULL,
     email TEXT NOT NULL,                 -- normalized lowercase
     phone TEXT,                          -- E.164, verified via SMS code when A2P is live
     password_hash TEXT NOT NULL,         -- argon2id (@node-rs/argon2) or bcryptjs cost 12 if native addon is a problem on Vercel
     name TEXT NOT NULL,
     email_verified_at TIMESTAMPTZ,
     member_id BIGINT REFERENCES vip_members(id),  -- link to the existing VIP row (free-pie code lives there)
     created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
     last_login_at TIMESTAMPTZ,
     UNIQUE (business, email)
   );
   CREATE TABLE account_sessions (
     id TEXT PRIMARY KEY,                 -- sha256 of a 32-byte random token; raw token only in the cookie
     account_id BIGINT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
     created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
     expires_at TIMESTAMPTZ NOT NULL,     -- 30 days sliding
     user_agent TEXT, ip TEXT
   );
   CREATE TABLE account_password_resets (token_hash TEXT PRIMARY KEY, account_id BIGINT NOT NULL, expires_at TIMESTAMPTZ NOT NULL, used_at TIMESTAMPTZ);
   CREATE TABLE saved_addresses (id BIGSERIAL PRIMARY KEY, account_id BIGINT NOT NULL, street TEXT, apt TEXT, city TEXT, state TEXT, zip TEXT, is_default BOOLEAN DEFAULT FALSE);
   ALTER TABLE web_orders ADD COLUMN account_id BIGINT REFERENCES accounts(id);
   ALTER TABLE web_orders ADD COLUMN discount_cents INT DEFAULT 0, ADD COLUMN fee_cents INT DEFAULT 0, ADD COLUMN town TEXT, ADD COLUMN promo_code TEXT, ADD COLUMN fulfillment TEXT;
   CREATE TABLE order_lines (             -- normalized history that survives menu changes
     id BIGSERIAL PRIMARY KEY,
     order_id BIGINT NOT NULL REFERENCES web_orders(id),
     account_id BIGINT,
     clover_item_id TEXT,                 -- stable key across renames
     item_name TEXT NOT NULL, category_id TEXT, qty INT NOT NULL, unit_cents INT NOT NULL,
     modifiers JSONB, created_at TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   CREATE INDEX ON order_lines (account_id, clover_item_id);
   ```
3. **Auth routes** (`api/account/*.ts`, all `.js` imports, all behind `rateLimitStrict` + Turnstile on signup/login/reset):
   `signup` (creates account + pending email verification; reuses `parkPendingSignupAndSendLink`; on verify → create/attach `vip_members` row and mint the `PIE-` code exactly as today), `login`, `logout`, `me` (account + free-pie code + status/expiry + last 10 orders + saved addresses + consent flags), `password-reset/request`, `password-reset/confirm`, `consent` (toggle SMS/email; writes `consent_events`), `orders` (paginated history), `reorder` (returns a cart payload for one past order).
   Session cookie: `__Host-gigis_session`, `HttpOnly; Secure; SameSite=Lax; Path=/`, 30-day sliding; CSRF: same-site + `Origin` header check on all POSTs (no tokens needed with SameSite=Lax and JSON bodies). Generic errors on login ("email or password is wrong"); constant-time compare; lock after 10 failures / 15 min per email+IP.
4. **Join flows on the site:**
   - "Free pizza pie" badge → `/account/` page (static prerendered shell + client fetch; no inline script) with **Create account** (name, email, phone, password, street/apt/city/state/zip, the two consent boxes with the existing consent text) → "Check your email" → verify link → account active, free-pie code shown immediately on the account page and in the welcome email.
   - **Checkout (biggest win):** after a successful guest order, the confirmation screen offers "Save this order to an account — just pick a password" with name/email/phone/address already filled from checkout (replaces `VipJoinInline`). Account gets the pie code; the just-placed order is attached (`web_orders.account_id`).
   - Logged-in checkout: name/phone/email/address prefilled, free-pie code auto-applied when eligible (pickup + Plain Pizza in cart), one-tap "Reorder my usual".
   - **Existing VIP members** (have a `PIE-` code, no password): "Already a VIP? Set your password" → enter email → verification link (reuse the existing flow) → set password → account created with `member_id` linked; their unexpired code shows up. No codes are re-minted; uniqueness stays enforced by the existing indexes.
5. **Upsell at checkout ("you usually add X"):** run when the cart drawer/checkout opens for a logged-in account:
   ```sql
   SELECT clover_item_id, item_name, COUNT(DISTINCT order_id) AS times, MAX(created_at) AS last_at
   FROM order_lines WHERE account_id = $1 AND created_at > now() - interval '180 days'
   GROUP BY 1,2 HAVING COUNT(DISTINCT order_id) >= 2
   ORDER BY times DESC, last_at DESC LIMIT 10;
   ```
   Rules: item ordered in ≥2 of the last N orders (or ≥40% of orders when N≥5), not already in the cart, currently available in the live catalog, max 3 suggestions, prefer sides/drinks/desserts over a second entrée, label "You usually add …" with one-tap Add. Guests keep the current generic rail. Log `upsell_impressions(account_id, item, shown_at, added BOOLEAN)` to measure lift; admin stats card "upsell adds / week".
6. **Order history capture:** in `api/order/create.ts` after the Clover order fires, write `order_lines` from the priced `kitchenLines` (item id, name, category, qty, unit price, modifiers) and set `web_orders.account_id` when a session cookie is present; for guests, also store `customer_email_lower` so a later account signup can **claim** past guest orders by verified email.
7. **One account for both locations?** Recommend **per-site accounts for phase 1** (the DBs are separate and the business keys differ), with the same email allowed at both. Phase 2: a shared `accounts` DB (or Neon Auth, which is already provisioned in both projects' env) and location-scoped memberships. Don't block phase 1 on it.
8. **Compliance:** keep the byte-identical consent text and the SMS double opt-in; consent toggles in the account page write `consent_events`; unsubscribe links keep working without login; password reset emails are transactional (not marketing); minimize PII in staff texts (last 4 of phone); GDPR/CCPA-style "delete my account" route that anonymizes `accounts` + `order_lines` but keeps the compliance records.
9. **Admin:** members list shows account status (guest / VIP-only / account), last order, lifetime orders, favorite items; "look up by phone" at the register; code redemption unchanged.
10. **Rollout (per site, SB first since it has fewer moving VIP surfaces):**
    - Slice 1 (2–3 days): migrations + `order_lines` capture + `account_id`/discount/fee columns on `web_orders` (fixes SB-16 too). No UI change.
    - Slice 2 (3–4 days): auth routes + `/account/` page + post-order "set a password" + existing-VIP password claim.
    - Slice 3 (2 days): logged-in checkout prefill + auto-apply pie + reorder.
    - Slice 4 (2–3 days): personalized upsell rail + impression logging + admin cards.
    - Then port to LB (mostly copy; LB also needs LB-3/LB-4 resolved first so shared codes and the QR path are coherent).
11. **Decisions needed from the owner:** email as username OK? per-location accounts for now? keep the 90-day pie expiry? phone verification required (waits on A2P) or email-only at launch? show prices/history across both locations later?
